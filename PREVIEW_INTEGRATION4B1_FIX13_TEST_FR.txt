PinteMod Control Center — Integration Preview 4B1 Fix13
TEST CIBLÉ — AUTO-RÉCUPÉRATION DE L’AGENT ET MISE À JOUR À UN SEUL EXE

OBJECTIF
- À partir de Fix13, ne plus devoir lancer manuellement chaque nouvelle version sur les deux PC.
- L’Agent installé sur le PC serveur est maintenu par une tâche Windows first-party fermée :
  ouverture de session + contrôle toutes les minutes.
- Si l’Agent tombe, Windows relance uniquement l’EXE Agent géré avec l’argument fixe --remote-agent.
- Aucun nouveau port, aucun PsExec, WinRM, raw shell ou commande distante arbitraire.

IMPORTANT — MIGRATION DE L’ANCIEN AGENT FIX9 DÉJÀ ARRÊTÉ
Le PC fixe ne peut pas démarrer par SMB un processus Windows qui est déjà arrêté.
Il faut donc UNE DERNIÈRE réactivation du vieil Agent afin que Fix13 puisse lui être poussée.
Il n’est PAS nécessaire de copier/lancer Fix13 manuellement sur le portable :
1. Sur le portable, avec l’ancien Control Center déjà présent, utiliser une seule fois
   « ACTIVER / MAJ AGENT SUR CE PC » pour remettre l’Agent actuel en marche.
2. Sur le PC fixe en Fix13, lancer « SYNCHRONISER LES DEUX PC ».
3. Fix13 doit être poussée vers le portable et le nouvel Agent doit installer lui-même
   l’auto-récupération Windows.

VALIDATION APRÈS MIGRATION
1. Vérifier que les deux PC annoncent 2.4.0-preview-integration.4b1.fix13.
2. Fermer le Control Center du portable : l’Agent doit rester en arrière-plan.
3. Si l’Agent est volontairement interrompu pour le test, attendre jusqu’à 90 secondes.
4. Depuis le PC fixe, ACTUALISER : le heartbeat Agent doit recommencer à évoluer.
5. Pour la version suivante, ne mettre le nouvel EXE QUE sur un seul PC puis utiliser
   « SYNCHRONISER LES DEUX PC » : l’autre côté doit se mettre à niveau sans lancer le nouvel EXE localement.

SÉCURITÉ
- La tâche Windows pointe uniquement vers :
  %LOCALAPPDATA%\PinteMod\ControlCenter\remote-agent\PinteMod.ControlCenter.exe --remote-agent
- Le chemin est fermé par le code ; aucun chemin/argument distant n’est accepté.
- Les packages de mise à jour restent protégés HMAC + SHA-256.
- Un marqueur temporaire empêche le mécanisme de récupération de relancer l’ancien Agent
  pendant les quelques secondes où son EXE est remplacé.
