Nous commençons le développement de **PinteMod Control Center v2.2**.

Lis intégralement, dans cet ordre :
1. `HANDOFF_PinteMod_ControlCenter_v2.2.md`
2. `AGENTS.md`
3. `WORKSPACE_SETUP_FR.md`
4. le contenu de `reference/PinteMod_v2.1.1_FINAL.zip`
5. les contrats JSON présents dans `contracts/`

La base serveur stable et unique est **PinteMod v2.1.1 FINAL**. Ne modifie jamais directement mon serveur de production. Le dossier `server-sandbox/` est une copie locale de test et doit rester exclu de Git.

## Objectif de cette première tâche

Créer le socle d'une application Windows locale en **C# / .NET 8 / WPF** avec une interface sombre moderne inspirée de `design/pintemod-control-center-reference.png`.

Cette première étape doit être **totalement read-only et entièrement simulée** :
- aucune commande RCON réelle ;
- aucune écriture dans PinteMod ;
- aucune modification GSC ;
- aucun accès distant ;
- aucun compte ni authentification ;
- aucun port réseau ajouté.

## Écrans attendus

- Dashboard
- Joueurs
- Serveur
- Records
- Logs
- Paramètres

Le Dashboard doit afficher avec des données simulées :
- carte actuelle et code de carte ;
- manche ;
- durée de session ;
- joueurs connectés / maximum ;
- état Ranked ou Unranked ;
- état Supervisor, Ban Service, GeoIP et PinteMod ;
- événements en direct ;
- liste des joueurs ;
- sélection d'un joueur et ouverture d'une fiche détaillée.

La fiche joueur doit préparer visuellement les futures actions :
- revive ;
- respawn ;
- points ;
- munitions ;
- armes ;
- atouts ;
- téléportation ;
- godmode ;
- mute ;
- kick ;
- ban ;
- rôle ;
- historique.

Ces boutons doivent être visibles mais clairement marqués **Simulation** et ne doivent encore rien envoyer.

## Architecture demandée

Créer une solution avec séparation claire :
- `PinteMod.ControlCenter` : WPF / présentation ;
- `PinteMod.ControlCenter.Core` : modèles, contrats et logique ;
- `PinteMod.ControlCenter.Infrastructure` : fournisseurs simulés puis futurs lecteurs locaux/RCON ;
- tests unitaires.

Utiliser des interfaces et l'injection de dépendances afin que les données simulées puissent être remplacées plus tard par :
- fichiers de session ;
- logs ;
- heartbeats ;
- snapshots JSON ;
- client RCON localhost.

## Contraintes graphiques

- fond très sombre ;
- accents bleu nuit et bleu électrique ;
- vert pour les états sains ;
- orange pour les avertissements ;
- rouge uniquement pour les erreurs et actions dangereuses ;
- cartes KPI sobres ;
- typographie moderne ;
- interface redimensionnable ;
- cible principale 1920×1080 ;
- animations très discrètes ;
- aucun aspect de console PowerShell.

## Livrables de cette tâche

1. architecture proposée avant modification ;
2. solution .NET 8 compilable ;
3. prototype WPF exécutable ;
4. données simulées réalistes ;
5. tests unitaires de base ;
6. README de compilation et lancement ;
7. liste précise des fichiers créés/modifiés ;
8. résultat des compilations Debug et Release ;
9. captures du prototype si l'environnement le permet.

Ne développe pas encore la communication RCON. Ne modifie pas les sources PinteMod validées. Commence par auditer l'archive et présente brièvement le plan d'implémentation, puis réalise la première version complète sans demander de confirmation intermédiaire sauf blocage réel.
